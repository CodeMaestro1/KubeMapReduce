[#2] Recovery respawn timeout does not scale with backlog
Source: Best practice (Per-operation timeout budgeting)
Fix: Replaced a single shared 2-minute recovery context with per-attempt spawn timeouts in `Scheduler.Recover`, so one slow spawn cannot consume the full budget and starve later recovered attempts.

[#3] Partial recovery spawn failures can terminate startup
Source: Best practice (Graceful degradation at startup)
Fix: Updated `Scheduler.Recover` to log and continue on spawn failures while still returning hard DB/query errors, preventing transient orchestration errors from aborting manager startup.

[#4] Kubernetes cleanup failures were only logged and then dropped
Source: Best practice (Eventual consistency reconciler pattern)
Fix: Added a scheduler cleanup retry queue plus `StartCleanupReconciler` background loop, and routed completion/failure/cancel cleanup calls through retry-aware cancellation logic.

[#5] Internal job-cancel endpoint lacked authentication
Source: Best practice (Defense in depth for internal control planes)
Fix: Added internal endpoint authorization for `DELETE /internal/jobs/{job_id}` using `X-Internal-Token` when `MANAGER_INTERNAL_API_KEY` is configured, with loopback-only fallback when unset.

[#6] `replica_index` coupling caused reduce scheduling starvation risk
Source: copilot-instructions.md
Fix: Adjusted idle-task selection so manager affinity is enforced for Map tasks while Reduce tasks are still schedulable regardless of partition index, and broadened recoverable-attempt lookup to job ownership derived from map-task affinity.

[#7] Stale-task reaper lock query missed `SKIP LOCKED`
Source: copilot-instructions.md
Fix: Updated stale-task selection SQL to `FOR UPDATE ... SKIP LOCKED` so concurrent reapers avoid lock contention and continue reclaiming expired attempts in parallel.

[#8] Cancelled jobs could leave orphan `Running` attempts and exhaust quota
Source: copilot-instructions.md
Fix: Applied the PostgreSQL/DDS instruction to keep `TASKS.current_attempt_id` state transitions consistent with `TASK_ATTEMPTS` in one transaction by failing active attempts during cancellation as tasks/jobs are updated.
Note: Better approach applied by also setting `end_time`, ensuring observability and preventing quota leakage from orphan `Running` attempts.

[#9] Global pod quota checks were not serialized under concurrent schedulers
Source: copilot-instructions.md
Fix: Applied the Resource Quota Enforcement pattern (query `SYSTEM_CONFIG.max_concurrent_pods` and running attempts before scheduling) and strengthened it with row locking via `FOR UPDATE` to keep concurrent decisions safe.
Note: Better approach applied by serializing quota decisions under contention, reducing oversubscription races without changing the existing quota model.

[#10] Reaper respawn loop reused a shared timeout context for all retries
Source: Best practice (Per-call deadline isolation)
Fix: Updated stale-task respawn logic to create a fresh timeout context per `SpawnWorker` call, preventing backlog retries from inheriting an expired context and failing immediately.
Note: No explicit per-call timeout recommendation exists in copilot-instructions.md; this hardening was applied as a robustness best practice.

[#11] Worker control-plane gRPC lacked configurable auth/TLS hardening
Source: Best practice (Zero-trust service-to-service defaults)
Fix: Added optional worker RPC token validation (`x-worker-token`), optional TLS cert/key server configuration, and disabled gRPC reflection by default unless explicitly enabled by environment.
Note: copilot-instructions.md mandates RPC fencing fields and behavior but does not prescribe transport/auth hardening; this stronger protection was applied as an additive best practice.

[#12] Register mismatch errors leaked current attempt identifiers
Source: copilot-instructions.md
Fix: Updated `WorkerServer.Register` to reject stale attempts with a generic `"attempt rejected"` message and server-side logging, aligning with the attempt-fencing rule that stale attempts should be rejected without exposing active credentials.

[#13] Worker RPC security controls were still permissive by default
Source: Best practice (Secure-by-default control plane hardening)
Fix: Added explicit startup validation that requires worker token auth and/or TLS unless `ALLOW_INSECURE_WORKER_RPC=true` is intentionally set for local development, preventing accidental insecure deployments.

[#14] Job listing endpoint returned unbounded result sets
Source: Best practice (Defensive pagination and bounded responses)
Fix: Added `limit`/`offset` pagination with validation and a server-side cap for `/jobs`, and wired pagination through `JobStore` (PostgreSQL and in-memory) to bound memory and latency under large histories.

[#15] Scheduler quota path held a global config row lock
Source: copilot-instructions.md

[#16] Task assignment transactions could hang indefinitely under DB latency
Source: Best practice (Bounded operation timeouts)
Fix: Added a bounded context timeout to `Scheduler.GetNextTask` so assignment transactions fail fast instead of holding open DB resources indefinitely when the database is slow or unresponsive.

[#17] Scheduler recovery path had no overall deadline for startup reconciliation
Source: Best practice (Startup deadline budgeting)
Fix: Added a global timeout to `Scheduler.Recover` and deadline-aware spawn loop behavior so startup recovery remains bounded and defers remaining work to the stale-task reaper instead of running unbounded.

[#18] Expired orphan attempts could remain `Running` and leak global quota
Source: Best practice (Lease lifecycle consistency)
Fix: Added `QueryFailOrphanExpiredAttempts` and executed it during `FailStaleTasks` transactions to close expired running attempts no longer referenced by `TASKS.current_attempt_id`, preventing quota leakage from stale orphan records.

[#19] API handlers accepted unbounded JSON request bodies
Source: Best practice (Defensive request size limits)
